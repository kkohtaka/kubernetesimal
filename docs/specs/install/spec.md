# Installing the operator

## Purpose

Someone who wants to use the operator applies one set of manifests and gets an operator that runs. Today the
manifests in the repository do not give that: the operator's Pod never becomes ready. This specification says what
installing has to result in.

## Scope

The manifests that install the operator: what `kubectl apply -k config/default` applies from a checkout, and the
`install.yaml` that a release publishes, which is the same thing with the image of that release.

### Out of scope

- What the operator does once it runs. See the [specification of etcd clusters](../etcd/spec.md).
- Installing what the operator needs: KubeVirt, and a network plugin that suits it.
- A Helm chart, and any other way of installing.
- Upgrading from one release to another, and uninstalling.
- Running more than one replica of the operator.

## Background

The manifests were generated by kubebuilder years ago and not kept up. They fail in three ways, see issue #294: the
image of the metrics proxy is no longer published, the operator is limited to 30Mi of memory, and it is configured
to send traces to a collector that is not part of the installation.

"A fresh cluster" below is a Kubernetes cluster of a supported version with KubeVirt installed and nothing else that
relates to this project.

## Requirements

- **INST-001**: Applying the manifests to a fresh cluster succeeds, and within five minutes the operator's
  Deployment reports that it is available.
- **INST-002**: The manifests need nothing in the cluster besides Kubernetes itself and KubeVirt. In particular they
  do not need cert-manager.
- **INST-003**: Every container image that the manifests name can be pulled without credentials.
- **INST-004**: The manifests in the repository name the operator image
  `ghcr.io/kkohtaka/kubernetesimal/kubernetesimal`. The `install.yaml` of a release names that image with the tag of
  the release.
- **INST-005**: As installed, the operator does not send traces anywhere, and does not log errors about sending
  them.
- **INST-006**: When the operator is given the address of an OpenTelemetry collector, it sends its traces there.
- **INST-007**: The operator's metrics cannot be read from another Pod without credentials.
- **INST-008**: While it creates an etcd cluster of three members, the operator's container is not restarted.
- **INST-009**: Applying the manifests a second time changes nothing and succeeds.
- **INST-010**: The operator runs with the permissions in the manifests. While it creates, resizes, and deletes an
  etcd cluster, the API server refuses none of its requests for lack of permission.

## API changes

None to the kinds. The `KubernetesimalConfig` kind, through which the operator reads its configuration file, loses
its dependency on a controller-runtime package that is deprecated, and keeps its fields.

## Permission changes

None are required by this specification. INST-010 is a check that the permissions which exist are enough.

## Open questions

None. The decisions that were taken while drafting are listed in the [plan](plan.md#decisions).
